# 前端工作台

一期前端只有一个目的：**让「看图 → 改图 → 再生成」这件事不离开同一个屏幕**。因此它不是表单页 + 画廊页的组合，而是一个两栏工作台：左边一条 72px 的图标导航，右边是内容区。

导航七项，用两条细分隔线分成三组：**首页 / 资产 / 工具 / 回收站 ‖ 图片 / 视频 ‖ 设置**，默认落地页是首页。文生图和图片编辑合并成「图片」——它们本来就是同一个创作框的两个模式，分成两个入口只会让人来回找。视频是独立的一页，而不是图片创作框的第三个 Tab：它的参数面（首帧 / 尾帧、时长、画幅档、音频）和图片几乎不重叠，混在一起会让那个框变成四组条件分支。工具是**不吃 GPU 的本地处理**，与生成流程完全分开；回收站紧挨着工具，因为它是「删除」的撤销入口，和创作无关。

| 页面 | 路径 | 做什么 |
| --- | --- | --- |
| 首页 | `/` | 落地页：两个创作入口（生成图片 / 生成视频）、本机设备与显存状态、最近作品、模型卡、灵感提示词 |
| 资产 | `/gallery` | 纯浏览：响应式网格，按日期分组、按生成时间从新到旧；hover 里有「本地编辑」直达编辑器 |
| 工具 | `/tools` | 工具目录：卡片网格，已有「图片编辑器」「序列帧工坊」，其余是计划中的占位卡 |
| 图片编辑器 | `/tools/editor` | 本地图片编辑器：抠背景、改画布尺寸、主体等比缩放、指定底边留白，导出 PNG 或**保存到资产** |
| 序列帧工坊 | `/tools/spriteforge` | **原版 SpriteForge 就地改造后内嵌**（同一文档、非 iframe）：序列帧播放预览、编辑轨道、多序列、分页导出都是上游实现。上游四个导入按钮现在都先弹「从本机上传 / 从资产选」，导出弹层多一个「保存到资产」（直接进素材）；`?video=<id>` / `?asset=<id>` 深链自动载入。全部在浏览器里完成，不经过后端。页面不再叠标题栏，回工具走左侧栏 |
| 回收站 | `/trash` | 撤销删除的地方：被删的图片 / 视频 / 素材按删除时间倒序列出，每件显示「还剩 N 天」，可以「恢复」或「彻底删除」，右上角「清空回收站」一次性删文件 |
| 图片 | `/compose` | 创作：批次流的作品 + 底部悬浮创作框（默认文生图，可在框内切编辑） |
| 视频 | `/video` | 视频工作台：只显示视频作品，底部是视频创作框（首帧 / 尾帧、时长、画幅） |
| 设置 | `/settings` | 系统状态 |

## 布局骨架（创作页）

```
┌────┬───────────────────────────────────────────────────────────┐
│    │ 顶栏：项目下拉 · 创作 15 个批次   搜索 / 日期 / 模型 / 收藏 / 视图 │
│ 侧 ├───────────────────────────────────────────────────────────┤
│ 边 │ 作品流（唯一的滚动容器）                                     │
│ 栏 │   今天  │ 批次 #21  ← 未出图的格子就是占位卡（排队中/进度）      │
│ 72 │   昨天  │ 批次 #20                                       │
│ px │   更早  │                                                 │
│    ├───────────────────────────────────────────────────────────┤
│    │ 创作框：模式切换 · 提示词 · 参考图 · 参数 pill · 生成按钮        │
└────┴───────────────────────────────────────────────────────────┘
```

## 布局骨架（资产页）

```
┌────┬───────────────────────────────────────────────────────────┐
│    │ 顶栏：项目下拉 · 资产 70 张   搜索 / 日期 / 模型 / 收藏（无视图切换）│
│ 侧 ├───────────────────────────────────────────────────────────┤
│ 边 │ 今天 44 张                                                  │
│ 栏 │  ▢ ▢ ▢ ▢ ▢ ▢ ▢   ← repeat(auto-fill, minmax(168px, 1fr))  │
│ 72 │  ▢ ▢ ▢ ▢ ▢ ▢ ▢                                             │
│ px │ 更早 26 张                                                  │
│    │  ▢ ▢ ▢ ▢ ▢ ▢ ▢           ← 没有创作框，只浏览、只做图片操作      │
└────┴───────────────────────────────────────────────────────────┘
```

资产页**不按批次分块**：同一批的几张图在这里只是时间相邻的几张图，按 `image.created_at` 倒序铺开。批次信息留在创作页——那里关心的是「这一批什么时候跑完」，而不是「历史上一共有什么」。

硬约束与实现方式：

| 约束 | 实现 |
| --- | --- |
| 只有两栏，禁止第三栏 | `app/layout.tsx` 里 `Sidebar`（72px 固定）+ `main`（`flex-1 min-w-0`）；参数一律走弹出层 |
| 作品流是主空间 | `main` 内部 `flex-col`：顶栏 `h-14 shrink-0`、作品流 `flex-1 overflow-y-auto`，创作框浮在作品流之上 |
| 创作框悬浮在底部 | 创作框是 `main`（`relative`）里的 `absolute inset-x-0 bottom-0`，**不是** `fixed`，所以不会横跨左导航；背后**没有渐变遮罩**——早先那层 `bg-gradient-to-t` 会把作品流盖成一片黑，现在创作框自己带半透明底，下面的图能整个透出来 |
| 页面不出现多层滚动条 | `body` 是 `h-screen overflow-hidden`，只有作品流和弹出层内部滚动 |
| 系统状态不进首页 | 搬到 `app/settings/page.tsx` |

## 状态放在哪里

- **服务端数据**：TanStack Query。`["generations", 筛选…, limit]` 与 `["models"]`、`["health"]`。
- **界面状态**：`useState`（筛选、视图、已关闭的失败条）+ Zustand（创作框、参考图）。
- **为什么创作框不用 URL query 参数**：`useSearchParams()` 在 layout 层的客户端组件里会让整个页面退出静态生成；而且输入到一半的提示词不该出现在地址栏和浏览器历史里。用 store 后切换页面也不丢草稿。
- **模式各存一份提示词**：`prompts[text_to_image]` 与 `prompts[image_edit]` 分开，切模式不会互相覆盖。
- **参考图跨页保留**：从作品流点「继续编辑」只写 store，然后 `router` 不需要跳转（已在首页），创作框自动切到编辑模式。

## 数据流

1. `GET /api/v1/generations`（带搜索/模型/日期/收藏筛选）返回 `GenerationRead[]`，每项自带 `tasks` 与 `images`。
2. `page.tsx` 把它扁平化成 `FeedSlot[]`：**一个任务一格**，`image` 可能为 `null`（还没出图），`index / total` 是它在这批里的位置，`seed` 取自该任务。兜底还会补上找不到任务的孤立图片。
3. 渲染分三层状态：
   - **作品流**：日期分组 → 批次分组 → 每张图（或占位卡），新批次一提交就出现在最终位置，不再有顶部的「进行中批次条」；
   - **占位卡**：`pending / queued` 显示「排队中」，`running` 显示 spinner 与百分比，底部有一条 0.5px 进度条；`failed` 显示失败原因，`cancelled` 显示已取消；卡片底栏固定是「第 N / M 张」与状态；
   - **详情弹窗**：单张图的全量元数据与操作（只对已有产物的卡可打开）。
4. 刷新：`useTaskEvents()` 订阅 `/api/v1/ws/tasks`，收到 `task.updated` 后 600ms 合并一次 `invalidateQueries`；同时只要列表里还有活动批次就 `refetchInterval: 1500`。两条路并行，WS 断了也不会卡在旧状态。
5. 提交：三选一，看模式和有没有参考图——`text_to_image` 且没有参考图 → `POST /generations`（JSON）；`text_to_image` 且有参考图 → `POST /generations/image-to-image`（multipart）；`image_edit` → `POST /generations/edit`（multipart，必须 1 张）。提交后立即返回，不等待推理；`onSettled` 里 1.2s 后再 invalidate 一次，接住「刚排上队」的那一瞬间。
6. 时间一律走 `lib/date.ts` 的 `parseIso()`：后端时间戳常常不带时区后缀，直接 `new Date()` 会被当成本地时间，导致时间早 8 小时、零点后的批次被分到「昨天」。

## 创作框的取舍

- **提示词默认是唯一的必填项**，负面提示词藏在「高级」里——绝大多数时候用不到，摆在明面上只会让人以为必须填。
- **参数做成 pill**：模型 / 比例+分辨率 / 数量 / 高级。点开才是面板，收起时只占一行。
- **高级设置按能力显隐**：`capabilities.exposes_steps / exposes_cfg / exposes_sampler / exposes_negative_prompt` 来自 `registry.yaml`。Turbo 的步数由固定 sigma 表决定，界面干脆不显示步数输入框，而不是让用户改了没效果；但它的 CFG 落在 `CFGGuider.cfg`、采样器落在 `KSamplerSelect.sampler_name`，都与 sigma 表无关，所以和标准版一样露出来（采样器的表是按 euler 调的，换别的观感会变，默认仍是 euler）。
- **负面提示词不占版面**：CFG=1 时 ComfyUI 会跳过负面分支，后端在「有负面提示词且用户没填 CFG」时会自动把 CFG 提到模型的 `negative_prompt_cfg`（标准 3.0 / Turbo 2.0）。这件事**不在创作框里解释**，只在详情弹窗的 CFG 字段里体现真实值——高级面板保持干净。
- **Seed 两种模式**：随机（默认）或固定；固定值存在时，N 张按 `seed, seed+1, …` 递增，便于复现一批中的某一张。
- **参考图**：点击或拖入，编辑模式下显示缩略图与移除按钮；**提交成功后清空**（图已经存到后端，下一次编辑应该重新选，否则容易拿旧图再提交一遍）。
- **图片生成里可选参考图**：同一个模式里，"参考图?"按钮是可选的输入，不是第三种模式——加了图就走图生图，没加就是纯文生图。最多 2 张（`MAX_GENERATION_REFS`），第 3 张会被前端拦下并提示。参考图**不改变输出比例**，所以尺寸 pill 仍按用户设置生效；输入框右下角会显示「参考图 N 张 · 1024×1024」。提交成功后参考图会被清空（已存到后端，重复提交时应重新选）。
- **模式切换不共用参考图**：编辑模式的参考图在 `stores/reference.ts`，生成模式的可选参考图在 `stores/generationRefs.ts`；从作品流点「继续编辑」只影响前者。
- **遮罩只属于第 1 张图**：图片编辑没有单独的「局部编辑」页签——第 1 张参考图有内容时，鼠标悬浮它会多出一个「遮罩」按钮（在缩略图**下面的图注行**里，不压在图上、也不和下面的参数行重叠），点开就是遮罩编辑器。画完应用，参考图格子后面自动多一个「遮罩」卡片（红色叠图缩略图，× 可移除，点缩略图可以接着改）。有遮罩时提交会带 `mask` 字段，后端把这一单路由到 `image_inpaint`（只重绘涂到的地方）；没有遮罩还是整图 `image_edit`。
- **遮罩跟着第 1 张图走**：换掉第 1 张参考图会把已有遮罩丢掉（遮罩是对着那张图画出来的，套到新图上没有意义）；提交成功后遮罩与参考图一起清空。
- **默认值对齐常用操作**：一次性出 4 张（`count: 4`），顶部日期默认「今天」——打开页面先看见今天做了什么，而不是被历史淹没。
- **提交成功清空输入框**：只用"提交时的提示词快照"清空，若提交返回前用户已经改了输入框内容（或切了模式），就不清，免得把下一条提示词吃掉。
- **防重复提交**：`isPending` 期间按钮显示 spinner 并禁用；提示词为空、或编辑模式没有参考图时按钮禁用；`⌘/Ctrl + Enter` 快捷提交。

## 作品流与详情

- hover 出操作：查看大图、收藏、继续编辑、下载、删除。触屏没有 hover 时点击整张卡进入详情，详情里同样有这些操作。
- 作品流是**两级分组**：先按日期（今天 / 昨天 / 更早），日期内再按**批次**（generation）分组。同一次生成的几张图始终连在一起，不会和其他批次混排；即使某批次只有 1 张，也独占一行，不会被并排拼在一起。
- 批次头一行给出「批次 #id · 已完成/总数 张 · 状态与进度 · 时间 · 提示词」，下面从左排开这一批的每个格子；列表视图同一批次是一个分组，行内显示「第 N 张 · 模型 · 尺寸 · 大小 · 时间」。
- **未出图的格子不空着**：每个任务占一格，`排队中 / 生成中` 就地显示占位卡（生成中带 spinner 与百分比进度条），出图后原地换成图片，所以新批次一提交就出现在最终位置，没有单独的「进行中任务条」。
- 已完成的批次里被删掉的图仍占一格：显示「图已被删除 / 无产物」，右上角一个垃圾桶可以把这个任务本身删掉。不偷偷跳过是因为「这一批出了 4 张、我删了 2 张」和「这一批只出了 2 张」是两件事，藏掉格子就分不清了。
- 日期分组用的是批次的 `created_at`，且时间解析统一走 `parseIso()`（后端时间戳常缺时区后缀），避免凌晨批次被分到「昨天」。
- 详情弹窗的「重新生成」把该批的提示词/模型/尺寸/数量填回创作框，而不是偷偷再发一次请求——由用户决定要不要改参数。视频还多一步：首帧 / 尾帧也从 `generation.reference_images` 取回字节填进槽位（取回失败就留空，不拦着用户自己再选），宽高反查成「比例 + 档位」用 `matchVideoSize()`（`lib/videoSize.ts`），反查不到就按最近的比例与档位兜底。

## 资产库

- 入口是侧栏第一项「资产」，路径 `/gallery`；它回答「我一共有哪些图」，创作页回答「这一批跑完了吗」。
- 数据同样来自 `GET /generations`（后端没有单独的「全站图片流」接口），但前端把每批的 `images` **摊平**成一个图片数组，按 `image.created_at` 从新到旧排；
- 分组只按日期（今天 / 昨天 / 更早），**不再按批次分块**——同一批的几张图在这里只是时间相邻的几张图；
- 网格是 `grid-template-columns: repeat(auto-fill, minmax(168px, 1fr))`，窄屏自动降列；
- 顶栏隐藏网格/列表切换（资产页只有网格），搜索 / 日期 / 模型 / 仅收藏照常可用；
- 图片、视频、素材在同一个网格里，但都有明确标记：视频是右上角「视频」角标 + 正中播放键 + 左下角时长，素材是「素材 · zip」角标（ZIP 用首张 PNG 当封面，所以也有预览；纯 JSON 显示文件牌）；不想要混排时用网格上方的「全部 / 图片 / 视频 / 素材」切换（对应 `GET /generations?media=`）；
- 视频卡片 hover 里有「在序列帧工坊打开」（`/tools/spriteforge?video=<id>`），素材卡片同样直达工坊（`?asset=<id>`），进去就能直接抽帧或导入图集；
- 点击卡片打开与创作页同一个 `ImageDetail`；「继续编辑 / 重新生成」会把参数填回创作框并 `router.push("/compose")`，否则填了也没地方用；「在序列帧工坊打开」对素材是 `?asset=<id>`、对视频是 `?video=<id>`。
- 图片操作（收藏 / 下载 / 删除 / 继续编辑 / 重新生成）抽在 `hooks/useImageActions.ts`，两个页面共用一份，避免两份实现慢慢跑偏。

### 管理模式

顶栏最右侧「管理」进入批量模式（再点变成「完成」），退出时清空选择：

- 每张图左上角出现复选框，**点整张卡就是选择/取消**，不再打开大图；已选中的卡有强调色描边；
- 批次头（`批次 #12 · 4/4 张 · 时间 · 提示词`）右侧有一个**只在鼠标悬浮时出现**的垃圾桶：
  点它把整个批次（任务 + 产物 + 记录）移进回收站，走 `DELETE /generations/{id}`。
  删除这张按钮不放在图片卡片的悬浮条里——那里已经有「只删这张图」，
  两个删除语义并排容易点错；「整批删」放在批次头，位置就说明了范围。
- 管理条在顶栏下方：`全选 / 取消全选`、`已选 N / M 张`、右侧 `删除所选`、`清空工作区`；
- `删除所选` 走 `POST /images/batch-delete`，只删选中的图（进回收站），批次记录留在作品流里（可能变成空批次）；
- `清空工作区` 走 `POST /images/clear`，把全部图片 + 全部生成记录移进回收站，危险色描边；两个操作都过一次 `ConfirmDialog`（不是 `window.confirm`，因为要把「删多少张、能不能恢复」写清楚——现在的答案是「能，30 天内」）；
- 清空时若还有任务在跑，后端返回 `409`，前端直接把后端那句话 toast 出来。

## 回收站

所有删除都只是**打戳**（`deleted_at`），文件还在磁盘上，所以删错的东西 30 天内都能捞回来。入口是侧栏「回收站」，路径 `/trash`。

```
┌────┬───────────────────────────────────────────────────────────┐
│    │ 项目下拉 · 回收站 2 件 · 30 天后自动彻底删除   全部/图片/视频/素材 · 清空回收站│
│ 侧 ├───────────────────────────────────────────────────────────┤
│ 边 │ ┌─────────┐ ┌─────────┐                                  │
│ 栏 │ │ 素材·png │ │ 视频     │  ← 左上类型徽标 / 右上「还剩 N 天」     │
│ 72 │ │ 还剩30天 │ │ 还剩 27 天│                                  │
│ px │ │ 时间·尺寸 │ │ 时间·尺寸 │                                  │
│    │ │ 恢复 彻底删除│ │ 恢复 彻底删除│                               │
└────┴───────────────────────────────────────────────────────────┘
```

- **列表来源**：`GET /recycle-bin?media=` 一次 60 件，按删除时间倒序；`days_left` 由后端算好，前端只管显示，「≤3 天」转危险色提醒快过期了。
- **恢复**：`POST /recycle-bin/restore`，一次可以恢复多件；恢复时后端会把所属任务与批次一起解冻，否则图回来了却卡在被删批次里看不见。恢复后 invalidate `["generations"]` / `["images"]`，作品流与资产页立刻能看到。
- **彻底删除 / 清空**：`DELETE /recycle-bin/{id}` 与 `POST /recycle-bin/clear`，这两个动作才真的删文件，所以都走 `ConfirmDialog`，文案明确写「会立刻从磁盘删除」「无法恢复」。
- **30 天自动过期**：不需要前端定时任务，后端在服务启动和每次打开回收站时清理过期条目，过期的条目在列表里直接消失。
- 缩略图走 `GET /images/{id}/thumbnail`——这个端点**不过滤**软删除，所以回收站里的卡片仍然有预览（恢复后原来的 URL 也还成立）。

## 还没做的

- 视频编辑、参考视频（r2v）、首尾帧的强度控制。
- 视频卡片没有 hover 预览（只能点开详情播放）。
- 项目内子目录：每个项目目前只有一层平铺的批次，没有文件夹/专辑概念。
- 资产页没有虚拟滚动（一次 60 张，靠「加载更多」），也没有多选与批量操作。
- 参考图多张（一期编辑只接受 1 张）、图片拖拽排序、批量选择。
- 虚拟滚动：目前一次最多渲染 40 张，靠「加载更多」翻页；上千张时需要换虚拟列表。
- 键盘导航与焦点陷阱（详情弹窗只做了 ESC 关闭）。

### 素材（assets）

- 素材不是新表，而是 `images` 里 `media_type = "asset"` 的行，所以收藏、下载、删除、批量删除、清空工作区全都免费复用；
- 它由两个地方产生：本地编辑器「保存到资产」、序列帧工坊「保存到资产」（ZIP / JSON / 单张 PNG）；
- 卡片的缩略图来自服务端（ZIP 取里面第一张 PNG 当封面）；纯 JSON 没图可压，前端用 `<img onError>` 退回文件牌；
- 素材不能「AI 编辑」，但可以「在序列帧工坊打开」，这是它自己的下游动作。
- **从资产打开 = 编辑那条素材**：`?asset=<id>` 深链或工坊里「从资产选」图集，会让页面绑定该素材 id，左下角出现「正在编辑素材 #id · 保存会覆盖它」，导出弹层按钮变成「保存并覆盖 #id」，保存走 `PUT /assets/{id}`（批次、产物 id、条数都不变）。本机导入、拖入文件、从视频新建都会解绑，走 `POST /assets` 新建；**新建成功后也会自动绑定**，所以同一次会话里连点两次保存不会存出两条。点提示条上的 × 可以随时改成另存为新素材。
